# R76 —— 孔的「真弧四角」换算法：从三角扇（针形三角 → 点状白虚线）到逐角精确裁剪

**触发**：用户 r75 反馈 ——「你最后说的残余，我有点没听懂。我去核验了，**触控板四个角，的确可以看到小的白线**，你指这个嘛」。

**先澄清"残余"是什么意思**：R74 报告里的"残余 0.12–0.17mm"是 `hole-arc-qa.mjs` 量的**几何数字**
（网格孔边到理想圆弧的最短距离），不是用户看到的那条线。用户看到的线是**另一个缺陷**——
本轮先归属、再修。

## 一、归属（铁律 11 ①：先回答"这段像素属于谁"）

1. 在高倍机位 `tpcorner`（1300×800, dark）里用中值滤波做背景、取 dev 最大的点 → 得到一条
   **点状白虚线**（周期性亮点，间距 ~10–15px）。
2. `scripts/max/ray-pick.mjs` 打这些点：命中 `#f3f3f4`（台面铝）、**y=11.5000**、face=(0,−1,0)、nHit=2–4。
3. 用 `.scratch/r76/vn.mjs`（逐像素顶点法线探针）取命中三角形的三个顶点：
   `[[67.45,11.5,102], [67.424,11.5,97.421], [67.45,11.5,97.2]]`
   —— **0.026mm 宽、4.8mm 长**的针形三角（顶点几乎共线），三个顶点法线都是 (0,1,0) → 不是着色问题。

⇒ 结论：白虚线 = **R74 的补片算法**（`plateHoleCorners`：从方角拉的三角扇）在**近切点处**产生的
针形三角。几何上它属于"角区该有的料"，但亚像素宽的长条光栅化必然断续 → 一条点状虚线。

## 二、算法：扫描线 + 逐角精确裁剪（补片整体删除）

`src/geom/solids.ts` `plateWithHoles`：
1. 孔恢复**真实圆角**（R74 曾把孔压成矩形再补角）；
2. 每个带端点处，把落在孔内的角按圆角矩形**精确投影**推回孔边（`projectOut`：
   直边区推 x/z、角区沿弧心径向推）；
3. x 断点若落在"带中点边界"与"本 z 真边界"之间 → 吸附到真边界（`clipCorner` 的 (b) 步，
   只对**该 x 断点所属的孔**做，避免孔与孔相切时按别人的边界拉跑偏）；
4. 孔的**两个 z 端**按弧长补 z 断点（每带跨角 ≤11.25°，弦高 ≤ rr(1−cos5.6°)），
   加在 `snap()` **之后**（近切点处断点本来就密，会被 SNAP=0.3 吃掉）；
5. 任一角推不出孔（多孔重叠区）→ 整块面作废，绝不硬塞成覆盖空腔的面。

**踩到的两个坑（都已修，值得记）**：
- `inHole` 只按 x 区间判定 → 点被推到 z=cz±hd（孔的上/下直边）后**仍被判在孔内** → 6 轮推不出去
  → 整块面作废 → 触控板角 θ=85° 处一条 **0.36mm 缺料**。修法：z 正好在上下直边上 = 边界，不算孔内。
- `clipCorner` 里 `ivm` 误写成用 `z` 求（应 `zm`）→ (b) 步恒不触发 → 孔边缺一条 0.28mm 的料（静默、无报错）。

## 三、独立尺子（新资产）

`scripts/max/hole-boundary-scan.mjs`：**不依赖拓扑边**，从弧心按角度向外步进，
用"点是否落在台面铝三角形内"找**可见孔边界**半径（`--sx/--sz` 指定象限）。
为什么不复用 `hole-arc-qa.mjs`：它把"只被一个三角形使用的边"当孔边界，
一旦网格出现 T 型接缝/梯形裁剪，这个集合会混进非孔边 → 读数不可比（同网格改写算法后它反而变大）。

读数（Δr = 首块料 − 理想半径，+ = 孔外多料/缺料、− = 料越界；单位 mm）：
| 角 | R74 后 | R76 |
|---|---|---|
| 触控板 FR | 0.228 / 0.280 / 0.360（θ=37.5/70/85°） | **≤0.02（最差 0.156 单点，θ=27.5°）** |
| 触控板 BR | — | **0.036** |
