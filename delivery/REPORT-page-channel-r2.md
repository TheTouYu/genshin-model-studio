## 3. 页面渲染器（新增 `web/draw/photo.html`）

既有 `preview-demo.html` 是编辑器视口（深蓝底 + 网格 + AmbientLight + 两盏平行光、无环境贴图、无色调映射），天生是 CAD 视口，拿它做"以假乱真"没有意义。新页：

- **PBR**：`MeshPhysicalMaterial`（浅色件 metalness 0.92 / roughness 0.30 / clearcoat；深色件 metalness 0.06 / roughness 0.55）；`side: DoubleSide`（本网格是三角汤、绕序不统一，单面会被背面剔除）。
- **环境**：程序化影棚（软箱 4.2 + 侧板 0.95/0.7 + 背光 1.5 + 地面反弹 0.35）→ CubeCamera 512 烘 cubemap → PMREM 成 IBL；ACES Filmic，曝光 0.95。
- **地面 + 接触阴影 + 倒影**：4×4m 地面板 + 软边阴影贴图 + 网格 y 镜像副本（不透明度 0.11）。
- **颗粒**：512×512 高斯颗粒贴图全屏叠加（opacity 0.085，每次拍摄换相位），复现裁判量到的"传感器噪声"。
- **屏幕**：`web/draw/screen-ui.png`（程序化 macOS 桌面，`scripts/max/make-screen-png.mjs`）贴到活动区（平面 UV）。
- **无 HUD**：`shoot()` 自动隐藏调试文字（第一轮曾因 HUD 文字当场作废一次盲测）。
- **API**：`__photo.ready / shoot(view,w,h) / cam({azim,elev,dist,fov,target}) / setBg / hud(on)`；视角表 front/hero/top/kb/ports/side/screen34/lid。

## 10. 最弱一环（结论）

**在验收图集的分辨率口径下，我的细节全部"被抹平"**：880px 长边的图集里，键帽字标（2.4mm）只占约 3px、屏幕窗口图标只占约 4px、端口内部结构更小——裁判的判据全部退化为"有没有可辨认的高频细节"，而真机参考图（尤其新补的 `键盘和触控板.png`、`俯视图.png`）恰恰是**近距特写**，字标/纹理清晰可读。

原因链：
1. 我一直在用**整机视角**出图（6 张都是整机），而参考图里 3 张是**局部特写**（键盘/顶盖/屏幕）——同分辨率下特写的细节密度高一个量级。
2. 页面通道的分辨率预算（1180×700 整机）不足以让键帽字标、端口内舌、触控板缝隙达到可辨认像素。
3. 因此"以假乱真"的战场应从**整机**转到**特写**：出特写图（键盘特写、顶盖特写、屏幕特写、端口特写），在这些视角下我的几何/字标/材质细节才有机会与参考图同尺度竞争。

**下一轮**：①出 6 张**特写视角**（kb-close / lid-close / screen-close / port-close / trackpad-close / hinge-close），与用户新参考图的特写配对；②端口内部结构（MagSafe 5 针、USB-C 内舌）；③触控板缝隙与玻璃反射；④键帽字标在图集分辨率下仍可读（加大字标对比度/字号到真机尺度）。
