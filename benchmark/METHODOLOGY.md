# 组件连接图分析（Connectivity Graph Analysis）
## 从受力出发的模型检查方法论（round5 起应用于基准测试与生产修复）

> 来源：用户三轮反馈（"轮心悬空"→"绳索悬空"→"横杆共用重叠"）中隐含的分析思路，
> 由工程侧推导为通用检查方法。核心一句话：
> **模型不是"画得像"，而是"连得上"——每个组件的每对受力关系都必须实体接触，每个空间位置不得被多个角色占用。**

---

## 一、方法论（从现象到本质的三步分析）

### 第 1 步：从受力出发，建立组件关系图

对模型做完整受力分析（重力向下），给每个组件回答两个问题：

| 问题 | 含义 |
|---|---|
| **它靠什么支撑？** | 该组件的载荷沿哪条路径传回地面（支撑链上游） |
| **它支撑什么？** | 哪些组件压/挂在它上面（支撑链下游） |

由此建立 **连接图 G(V, E)**：
- 节点 V = 每个组件（含地面）
- 边 E = 组件间的**受力/连接关系**，每条边标注：
  - **连接方式**：实体接触（贴面/插入/套接）还是悬空（数值接近但无接触）
  - **方向**：谁支撑谁（沿重力向上游传导）
  - **角色**：结构件（承压/承拉）vs 悬挂件（吊挂载荷）vs 连接件（传递）

### 第 2 步：逐一检查两两关系（逐对核验）

对图中每一对组件，按"应当连接 / 应当分离"分类检查：

**应当连接的对**（受力链上相邻）：
- 实体接触判据：`两组件表面最近距离 ≤ 0`（允许插入；容差 = 组件半径/厚度之和）
- 违反 = **悬空**（violation，带具体间隙数值）

**应当分离的对**（无受力关系、可能相对运动）：
- 空间分离判据：包围盒/柱体不相交（留最小间隙）
- 违反 = **重叠**（violation）

### 第 3 步：重叠分析（角色冲突检查）

- 每个组件标注**角色**（支撑/悬挂/连接/载荷）
- **同一实体不得承担两个角色的功能**——尤其：
  - 结构连接件（如环间横杆）与悬挂挂点（如绳索挂杆）**必须分开设计**
  - 若共用：悬挂系（绳索/座舱）与结构系（轮/支撑）在转动时必然干涉 → 物理重叠
- 检查：两个不同角色的组件在空间中是否共位/相交

### 本质结论（现象 → 本质）

| 现象（用户可见） | 本质（数据可证） |
|---|---|
| 支撑杆与环"看起来连着"却悬空 | 模型用**坐标近似**代替**实体接触**：组件有半径/厚度，坐标点只是中心线，端点永远差一个尺寸 |
| 绳索两端悬空 | 组件导出语义与模型预期不符（如 el-disc 导出高=thick 而非 2×ry） |
| 横杆又连结构又挂绳 → 重叠 | 模型未做**角色分离**：一个组件被复用承担两个功能 |
| 两版设计"几乎相同" | 同一任务+同一提示词 → 结构收敛，**不是抄袭**（需查会话记录核实） |

## 二、落地为可执行检查（round5 实现）

### 连接点核验清单（T6 摩天轮，逐对）

```
受力链：地面 → 支架杆(4) → 轮毂轴盘 → 轮辐(6) → 环连接横杆(6,z向)
        → 双环 → 环连接横杆 → 轮辐 → 挂杆(6,切线向) → 绳索(6) → 座舱(6)

连接对（应当接触，间隙 ≤ 0）：
  1. 支架底 — 地面          （最低 y = 0）
  2. 支架顶 — 轴盘端面      （z=±0.2225 杆内侧贴轴端面 z=±0.21）
  3. 轮辐内端 — 轴盘外缘    （贴面：r内 = 0.055 + 0.006）
  4. 轮辐外端 — 横杆侧面    （插入 ≥ 0.008）
  5. 横杆两端 — 环内面      （插入 ≥ 0.010）
  6. 挂杆根 — 轮辐中心线    （两杆实体相交）
  7. 绳索上端 — 挂杆悬臂端  （插入 ≥ 0.002）
  8. 绳索下端 — 座舱顶      （插入 ≥ 0.005）

分离对（应当分离，不重叠）：
  9. 挂杆/绳索/座舱 — 横杆  （悬挂系 r < 横杆表面 r - 杆半径）
 10. 座舱 — 环              （座舱 z∈[-0.1,0.1] < 环内面 z=±0.1075）
 11. 支架 — 环              （z=±0.2225 与 z=±0.12 分离）
 12. 座舱底 — 地面          （最低吊舱悬空，不接地）

角色分离：
 13. 环连接横杆 = 纯结构（连两环+承接轮辐），挂杆 = 纯悬挂（不承担环连接）
```

### 执行方式
- 组件脚本交付 → `scripts/run-gms-model.sh` 管道 → items.json
- 确定性核验脚本（`benchmark/tasks/T6/validator.ts` + 连接图核验）→ 间隙表 / 悬空清单 / 重叠清单
- 输出：`{score, breakdown, violations, parse_ok}`（violations 带具体间隙数值，可直接回给模型修）

## 三、API 语义坑（从数据核验发现的，已确认/已修复）

1. **el-disc 的 rotation 覆盖 axis 默认朝向**（确认存在）：
   - `el-disc {axis:'front'}` → 导出轴向 Z（盘面朝前，横躺圆柱）
   - `el-disc {axis:'front', rotation:[0,0,0]}` → 导出轴向 Y（竖直）
   - 模型若省略 rotation 会得到横躺座舱；**必须显式 rotation:[0,0,0]** 才能竖直
2. **el-disc 导出 = 圆柱 {直径 = 2×max(rx,ry)，高 = thick}**：
   - ry 只影响直径，不影响高度；高度由 thick 决定
   - 模型用 ry 规划高度 → 座舱比预期矮一半 → 绳索下端悬空
3. **rod/disc/ring 导出均为圆柱基本件**（环被采样成 364 段切线方向短柱）：
   - 线段方向/位置导出**正确**（受控实验验证）；无方向 bug

## 四、抄袭核实结论（round4 用户疑点）

- A/B 两会话历史：工具调用仅 `mkdir`/`ls`，**无读取对方产物或项目文件行为**
- 脚本文本归一化相似度：0.00–0.01（30-char n-gram）
- items 几何签名逐项相同数：0
- 结论：**不是抄袭**。两版"看起来像"是同一任务+同一提示词下结构收敛的正常现象；
  用户看到的重叠/悬空是双方共同的方法缺陷（坐标近似 + 角色复用）。

## 五、方法论 API 化（十八期落地：从"文档约束"升级为"真实能力"）

> 用户要求：只靠方法论文档约束效果有限，应把方法论设计成**真实可用的 API 能力**，
> 让模型表达连接/受力关系时不再靠坐标心算。

### 新增 gms API（web/index.html，十八期）

| API | 方法论步骤 | 作用 |
|---|---|---|
| `gms.part(..., {name})` | — | 命名组件并登记世界几何（rod 线段/cyl 圆柱/ring 环管/box 盒体） |
| `gms.point(name, slot)` | — | 锚点：组件表面世界坐标（center/top/bottom/front/back/end1/end2）——模型不再心算端点 |
| `gms.touches(a, b)` | 第 2 步 | 两组件实体最近间隙（负=相交），contact 判定 ≤ 0.001 |
| `gms.link(a, b, {support})` | 第 1 步 | **声明受力连接**并硬校验实体接触（未接触直接抛错，带间隙值）；support 记录谁支撑谁 |
| `gms.floating()` | 第 2 步 | 悬空清单：无支撑链到地面的组件（BFS，接触点局部 y 判定方向） |
| `gms.collides()` | 第 3 步 | 未声明（非 link）的重叠对（实体相交 > 5mm） |
| `gms.verify()` | 汇总 | 一键校验：links 接触 + floating 空 + collides 空 → ok |
| `gms.parts()` | — | 命名组件清单（含 bbox） |

### 关键实现语义（踩坑记录）
1. **线段-线段最近距离**：f = d2·(r−p) 约定下，无约束解 s*=(c·e+b·f)/denom；
   边界修正顶点在 s=c/a（t=0）或 s=(c+b)/a（t=1）——符号写反会差出 1.4m 级错误。
2. **支撑方向判定用"接触点局部 y"**，不用整组件 bbox：斜撑（顶=被支撑件中部）、
   大环（底远低于接触点）、悬挂（支撑者在被支撑者上方）都必须按接触点判定，否则误报 floating。
3. **el-disc 导出语义**（前文）：rotation 覆盖 axis 默认朝向；显式 rotation:[0,0,0]+front → 轴向 Y。
4. 约束是**硬性的**：link 未接触抛错（带间隙）→ 模型必须修，比文档约束可靠。

### 模型工作流（推荐写法）
```js
gms.part('rod', {name:'spoke30', x1:px*0.061, y1:H+py*0.061, x2:px*0.738, y2:H+py*0.738, z:0, size:0.012});
gms.part('disc', {name:'sbeam30', x:px*R, y:H+py*R, z:0, r:0.02, thick:0.235, axis:'front'});
// …生成全部组件后，声明受力链：
gms.link('spoke30','hub',{support:'b'});   // hub 支撑 spoke30
gms.link('spoke30','sbeam30',{support:'a'});
gms.link('sbeam30','ringA');
// 未接触 → link 抛错（带间隙），模型据此修正坐标；
// 全部 link 通过后：
var r = gms.verify();   // {ok, links, floating, collides}
// ok=false → 按 floating/collides 清单继续修
```
