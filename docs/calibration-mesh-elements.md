## 0. 目标

用**最小校准板**在游戏/编辑器里对照三类元件，闭合它们的视觉语义（朝向 / 双面性 /
尺寸映射 / 是否呈现几何），并把结论回写到资源表（`src/core/resource-meta.ts` +
`docs/input-format.md` + `README.md`），作为后续一切网格化导出（`gms.part('mesh')`、
面板化、放样）的信任前提。

**不破坏现状**：未能在游戏/编辑器验证的项一律保持「未校准」，**不得写入主干文档当作
「已闭合」**。只有本任务书的对照结论明确通过后才可在资源表把对应项改为「已闭合」。

## 1. 校准包

由 `npm run gen-calibration` 生成（确定性、可重跑）：

```
delivery/calibration-mesh/
  MANIFEST.json                    # 汇总：样例、单元数、字节、开放项
  a1-plane-unit/                   # 10009003 平面 单位 1×1
  a2-plane-scaled/                 # 10009003 平面 缩放 0.5×0.3
  a3-plane-rotated45/              # 10009003 平面 斜 45°
  b1-tri-equilateral/              # 10009006 三棱锥 压扁正三角
  b2-tri-oblique/                  # 10009006 三棱锥 任意斜三角
  c-mesh-direct/                   # 10009019 网格元件直出（不携几何）
  d1-grid-panelized/               # 3×3 方格面 → 9 平面元件
  d2-cylinder-panelized/           # 4 段开口圆柱 → 4 平面元件
```

每个样例包含：`input.json`（输入）、`structure.json`（规范化结构）、`model.gil` /
`model.gia`（候选）、`summary.json`（单元数 + 字节 + 观察点）。

**注意**：`model.gil` / `model.gia` 仅为候选，未写回真实地图。写回由 genshin-ts 适配器
负责（本任务只做对照观察）。

## 2. 导入 / 对照步骤

### 2.1 方式 A：游戏 / 编辑器直接加载（需要你操作）

1. 用编辑器「导入候选」加载 `delivery/calibration-mesh/*/model.gil`（或 `.gia`）。
2. 若编辑器只认导出到真实地图，交给 genshin-ts 适配器把候选写回一张测试地图
   （模板 = 空模型，项 = 官方基础元件）。
3. 依次查看每个样例，按下表逐项记录。

### 2.2 方式 B：交给 genshin-ts 适配器

把 `delivery/calibration-mesh/*/structure.json` 作为输入，adaptor 生成地图后打开。
`structure.json` 已含规范化后的 item、prefabId、auxId 计划，可直接被适配器消费。

## 3. 观察清单

> 每项命中「渲染正确 / 语义符合」记为「已闭合」；无法确定 / 与猜想不符记为「未校准」；
> 需要重测记为「需复测」。

| 样例 | 资源 | 观察点 |
| --- | --- | --- |
| `a1-plane-unit` | 10009003 平面 | 零旋转是否平躺、法线是否朝 +Y；正面/背面是否同色可见（双面性）；`scale=[1,1,1]` 是否呈现 1×1 |
| `a2-plane-scaled` | 10009003 平面 | `scale=[0.5,1,0.3]` 是否呈现宽 0.5 × 深 0.3（X/Z 是否对应宽/深）；是否仍水平 |
| `a3-plane-rotated45` | 10009003 平面 | 绕 Y 转 45° 后是否斜置；是否仍为 1×1 |
| `b1-tri-equilateral` | 10009006 三棱锥 | `scale.y→0` 是否压成一个三角形的面（正三角形）；三角面是否落在 XZ 平面（法线 ±Y）；是否仍可见 |
| `b2-tri-oblique` | 10009006 三棱锥 | 缩放+旋转后是否得到不等边三角形；不等边比例是否随 `scale.x/z` 精确可控（任意三角形可从缩放旋转得到） |
| `c-mesh-direct` | 10009019 网格 | 直出的 `.gia/.gil` 只有 resourceId+变换（不携几何）；游戏侧**是否按 vertices/faces 渲染几何**；若为空壳 → 走「面板化」路径 |
| `d1-grid-panelized` | 10009003 平面(×9) | 9 个平面元件是否构成 3×3 方格面；是否双面可见；相邻格无缝/重叠 |
| `d2-cylinder-panelized` | 10009003 平面(×4) | 4 个平面元件是否绕 Y 成开口圆柱；各面法线是否沿径向外指；**平面绕法线的滚转**（宽度/深度映射）是否偏差 |

**原则**：只要该资源在游戏里的表现与「已闭合」的记录冲突，就标回「未校准」，不要沿用
旧文档里的乐观结论。

## 5. 回写规则（防漂移）

- 只有标「已闭合」的项，才把 `src/core/resource-meta.ts` 对应行 `status` 改为「已闭合」
  并同步 `docs/input-format.md` / `README.md`（用 `npm run gen-resource-table` 校验）。
- 「未校准 / 需复测」项保持「未校准」，**不得**改为「已闭合」。
- 任何改动后跑 `npm test`，其中 `tests/resource-table.test.ts` 负责在资源表三处与权威来源
  不一致时失败。
