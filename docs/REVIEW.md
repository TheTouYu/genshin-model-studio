# REVIEW：论文范式引入 A/B 基准验证（2026-08-15）

> 任务：《压缩三维为二维》实证论文（`voxel-3d-to-2d/`）工程范式实质性引入 Genshin Model Studio，
> 并建立客观 A/B 测试体系驱动验证。本文为阶段 4 收尾交付。

## 1. 借鉴了论文的哪些观点（逐条对应）

| 论文结论 | 本项目的落点 |
|---|---|
| ① 精确规格下表示方式不是瓶颈（全满分） | 实测复现：T1/T2/T3/T5 精确规格任务全部 1.0000，且与协议版本无关——**结论 ① 在本项目域成立**（详见 §5 天花板分析） |
| ② 自由生成下 2D 切片显著优于直接 3D 坐标 | 协议层面落地：v2「分层 2D 推理」协议（先 XZ 平面图 → 逐层 Y 堆叠 → 不变量自查）成为版本候选；本项目 T4 规模下两协议均满分，未触发论文的"壳"式缺陷（需更大规模任务才能验证，见 §7 未做项） |
| ③ 三视图是好"图纸"不是好"状态" | ADR-0003 提案 a：状态表（structure.json items）唯一、三视图只是派生投影（ADR-0002 已定 2D 画布）；投影一致性校验列为产品侧后续项（未做项理由见 §7） |
| ④ 工程范式："二维是推理画布，三维一致性交给确定性代数兜底" | **实质性落地**：确定性校验+保守修复管线（贴地吸附/支撑修复/轴对齐吸附/去重）→ 产品接口 `POST /api/validate-model`（`repair` 开关），"修复不了的如实报告"取代"静默输出坏模型" |
| ⑤ 列式物理是 2D 压缩的理想形态 | T5 重力任务：确定性重力求解器按"中心点支撑"逐列分解；模型两次均精确复现求解器结果 |
| 方法学：小样本方向性、重复取均值、方向翻转容错、评分器缺陷全量重算 | 基准体系全部采纳：T4 每条件 2 次取均值；盒体绕 Y k×90° 等价类规范化（不算加分）；`--rescore` 离线重算；任务文件冻结 hash + 勘误流程 |

## 4. A/B 差距归因

1. **差距为零 = 天花板效应，不是版本无效**：全部 24 次有效运行得分 1.0000。
   与论文结论 ① 完全一致——模型在"规格足够精确/规模足够小"时对表示与协议不敏感。
   本项目任务规模（3~12 个官方元件，连续坐标）远小于论文的 8×8×8 体素世界
   （60~150 个方块需同时跟踪），未触碰到论文结论 ② 的分水岭（坐标模式"三维心智模型崩溃"）。
2. **v1（修复管线）的独立贡献可观测为零**：raw score 与管线后得分均为 1.0000——
   合法结构的修复幂等性（零改动）在真实输出上得到验证；管线的价值体现在坏输出的兜底
   （单测覆盖：悬空/入地/非轴对齐被检出并保守修复，无支撑体时如实报告）。
3. **协议差异（v0 vs v2）在 T4 上不可区分**：自由生成 4 次（每条件 2 次）全部产出
   满足全部不变量的四腿桌（两个会话各自稳定的设计）。论文的分化需要更大规模自由生成。
4. **过程发现的两个真实失败模式**（旧会话，已存档 OLD-*.json，不参与打分）：
   - 输出协议失败：模型只输出推理文字、最终 JSON 未落地（连续 3 次）→ 解析失败记 0 分。
     根因疑似会话历史污染 + 输出长度预算；教训写入 benchmark/README.md 操作协议；
   - 重复消息污染：向排队中的会话重发消息会产生"元评论"回合。
5. **会话公平性保障**：两会话系统提示词逐字一致（仅身份标记不同）；任务提示词逐字相同
   （promptSha256 与冻结 hash 双重校验，不一致 = 运行失败拒绝写结果）；
   校验器实现、对方输出、汇总分数从未进入会话。

## 5. 结论（可测量指标 vs 预期）

| ADR-0003 提案 | 预期指标 | 实测 |
|---|---|---|
| a 投影一致性校验 | T4 投影违规数下降（诊断指标） | 未落地为代码（见 §7）；方案与接口设计已定 |
| b 校验+修复管线 | T4/T5 提升、T1/T2/T3 不变（幂等） | T1-T5 全部不变且满分；幂等性单测+真实输出验证；产品接口已落地 |
| c 双模式输入协议 | T4 提升 0.1~0.3 | 协议已实现（v0 直接 / v2 分层）；任务规模下无差异（天花板） |
| d 列式分解 | T5 满分保持 | T5 两轮满分，模型精确复现确定性求解器 |

## 6. 阻塞点（如实列出）

1. **基准区分度不足**：五类任务在当前规模下全部触顶，无法对协议候选给出正/负判定——
   这是"测量装置"的局限，不是版本的局限；继续跑第 3 轮只会重复天花板数据（已按停止条件终止）。
2. **自由生成任务规模偏小**：T4 只要求 5 个元件，远低于论文触发"壳"式缺陷的复杂度
   （60+ 坐标同时跟踪）；解析失败类缺陷（不输出 JSON）反而成为当前最可能的分化来源。
3. **会话输出长度预算**：一次"只推理不落 JSON"的观测表明输出截断是真实风险；
   修复管线对解析失败无能为力（不是 JSON 就没有可修的东西）。

## 7. 未做项与理由

| 未做项 | 理由 |
|---|---|
| 第 3 轮（v2 vs v3 自检回退协议） | 停止条件"连续两轮无提升"已触发，任务明示"不硬撑"；v3 协议文本已设计好，留待更大规模任务落地后复用 |
| 更大规模/更复杂的自由生成任务（如 20+ 元件书架、多步编辑一致性） | 新增任务须走完整 freeze 流程；当前五类任务已按约定冻结，中途加任务会破坏"先冻结后优化"的纪律——列为后续工作（论文局限清单同款：更大世界规模、多步编辑） |
| 提案 a 的投影一致性校验代码 | 基准五任务不含三视图投影评分（无法被确定性判定的视图任务不入选原则）；产品侧画布三视图校验需要前端配合，未在本轮范围内 |
| 几何核心提升为 src/core/geometry.ts | 当前 src/core/invariants.ts 复用 src/benchmark/geo.ts（单一真相源），解耦重构属架构级变更，按硬约束不擅动 |
| .gil/.gia 编码链路接入校验结果 | 编码器已稳定（29 条 golden），校验/修复发生在编码之前（API 层），无需改动编码器 |

## 8. 评估标准自评

1. 每条优化可追溯到论文依据并绑定可测量指标：✔（ADR-0003 每提案含论文依据+指标+风险+回滚）
2. 29 条 golden 零回归、新逻辑有新增测试：✔（86 条全绿；基准 18 条 + 产品接口 5 条新增）
3. 校验器确定性、可离线重算：✔（纯确定性代码；`score-round --rescore` 全量重算；统一输出 {score, breakdown, violations, parse_ok}）
4. 每轮完整 A/B 得分记录与运行证据：✔（results.json 趋势表 + runs/roundN 原始存档 + 本 REVIEW）
5. 文档与代码一致、ADR 可读：✔（principles / ADR-0003 / benchmark README / 本 REVIEW 与代码同步）

## 9. 一句话总结

论文范式已在工程侧实质落地（校验+修复管线进入产品 API），A/B 测量装置完整可用且验证了
"精确规格天花板"（与论文结论 ① 一致）；但当前任务规模无法复现论文的自由生成分化
（结论 ②），下一轮研究应在更大规模自由生成任务上验证 v2/v3 分层 2D 协议——装置已就绪，只差任务规模。
