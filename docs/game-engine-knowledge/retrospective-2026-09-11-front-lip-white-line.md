## 二、最后一次错误的完整调查链（R71 → R72）

1. **现象**（用户截图 + 文字）：「从正面看，它为什么和两边的颜色差这么远，颜色发生了突变？而且这个材质不对，应该和正面看的那一条面材质类似才对。」
2. **用户要求先讨论、不许动手** → 只做取证：「请你和我探讨，不要直接动手」。
3. **射线取证（决定性）**：在 `scoopz` 机位取「画面最亮像素」与「同一行最暗像素」各打一条射线：
   - 最亮 `px=150,353` → `#f3f3f4` @ (**−1.543, 5.617, 110.600**)，`face=(0,0,1)`；
   - 最暗 `px=844,353` → `#f3f3f4` @ (38.163, 7.521, **110.600**)，`face=(0,0,1)`。
   → **同一个面**（机身前壁平面 z=110.600、几何法线 +Z、同一铝材质）。一个平面、法线处处相同，**不可能自己一亮一暗** ⇒ 只可能是**着色法线**被改。
4. **机制**：凹槽置换窗口 `z > 102.6`、`y ∈ (yLo=deckY−5.0, yCap=deckY+0.02)`、`|x| < 25.5mm`。这个 y 区间本意是「让下沉量沿墙向下渐隐」，但它**覆盖了整段前壁高度**；而 R65/R70 的解析法线判据是 `flat[v] || moved[v] || deckPlane` —— `moved` 的语义是「**被下沉移动过**」⇒ 前壁顶点也进了解析法线分支 ⇒ 法线被写成「朝上」⇒ 窗口内按台面着色（吃头顶柔光箱→近白）、窗口外按竖直着色（反射暗房间→近黑），分界线正是 51mm 窗口边。
5. **修复**（`src/model/macbook/geometry.ts`）：
   ```ts
   const horiz = Math.abs(raw.nrm[v * 3 + 1]) > 0.999;   // 原始法线朝天 = 水平面族
   if (horiz || flat[v]) { ... 解析法线 ... }             // flat/deckPlane 均为 horiz 子集
   ```
   即：**按不变量（面族）判定，而不是按「是否被某个操作碰过」判定**。
6. **验证（二元 + 同口径）**：
   - `lipfront`(1200×700/dark) 唇口带：mean **187.7 → 50.9**、亮面(>200) **55.54% → 0.00%**、同行 p50 **247 → 50**（整条竖壁变为均匀）；
   - `groove34` 回归：台面/凹槽底带 `rows290:340` **100.4 → 97.0**（保住 R65/R70 成果）；前壁带窗口内 144.1 → 90.0；**窗口外左右两侧 41.5 / 190.6 逐值不变（+0.0）**——最终证明改动**只**发生在该 51mm 窗口内；
   - 结构不变：顶点数/三角形数不变（纯着色层）；`npm test` 252/252；
   - 用户核验：「修复了」。

## 三、为什么这个 bug 耗时最长——三条系统性根因

### 根因 1：**归属缺失的消融**（chasing symptom without attribution）
前 5 组对照实验全部打在**错误的物理对象**上（把前唇当触控板缝），后续 5+ 轮消融打在错误部位。**规律：任何一个「亮点/亮线/暗带」在被解释之前，必须先回答「这段像素属于哪个面、哪个网格、哪个材质」**——归属三件套（`ray-pick.mjs` 命中分类 + 色标 mesh + `tri-at.mjs` 竖直柱堆栈）每次都比一轮消融便宜得多，且一次就把搜索空间砍掉一个量级（R51/R57 各一次就锁定了面）。归属工具我早在 R42 就做了雏形，却拖到 R57 才当成「动手前必跑」。

### 根因 2：**实验可信度没有前置门**（空实验静默通过）
本轮至少 4 次「读数不变」其实是**实验没发生**：
- python `str.replace` 锚点不匹配 → **静默 0 次替换**（含写进 `&&` 链、`cp` 因目录不存在失败而短路吞掉整段）；
- 改了 `src/**` 但没 `npm run build` —— 而 `scripts/max/page-mesh.mjs` **import 的是 `dist/`** → 网格根本没变；
- 渲染通道吃到缓存旧页 / 旧网格（`?v=` cache-bust 未加、页面优先读 `.json.gz` 而我改了明文 JSON）；
- 指标口径漂移（早期「全帧亮>200 占比」实际量的是**屏幕 Dock 图标**，导致 R47–R53 的结论整批作废）。
→ **规律：每个实验必须自带「实验确实发生了」的证据**（替换计数 ≥1、`grep dist` 命中、verts/tris 或 md5 变化），否则该读数**不得进入推理**。

### 根因 3：补丁按「历史」而非「不变量」判定 → 修一处、污染一处
R65 的判据 `moved[v]`（被下沉移动过）是**过程性**的；R70 把它扩大；R72 才改成**面族**（原始法线方向）这种**不变量**。过程性判据必然随窗口/参数漂移而误伤邻域（此处误伤整段前壁），于是「修好 A 处 → 冒出 B 处症状」循环。
→ **规律：凡是批量改法线/材质/可见性的补丁，判据只能写「这个面是什么」（面族、法线方向、材质、共享边），不能写「这个面被谁碰过」。**
