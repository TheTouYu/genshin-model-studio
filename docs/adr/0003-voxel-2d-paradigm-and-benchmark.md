# ADR-0003：引入"二维推理画布 + 确定性代数兜底"工程范式

状态：提案（阶段 1 交付；采纳与否由 benchmark A/B 数据驱动，见 §6 指标）
日期：2026-08
关联：ADR-0001（3D 点集 + transform）、ADR-0002（2D 画布 + 视图投影）、docs/principles/voxel-2d-paradigm.md

## 背景

实证论文《压缩三维为二维》（仓库 `voxel-3d-to-2d/`，26 次真实 API 调用 + 确定性校验器）结论：

1. 精确规格下三种表示全部满分——表示方式不是精确任务的瓶颈；
2. 自由生成下逐层 2D 切片显著优于直接 3D 坐标——后者系统性产生"壳"式缺陷（环形地板/悬空屋顶/门高不足/漏窗）；
3. 三视图是好"图纸"但不是好"状态"（离散断层成像：投影有歧义）；
4. 工程范式："二维是模型的推理画布，三维一致性交给确定性代数兜底"——生成后跑不变量校验并自动修复。

本项目现状：三维数据（structure.json items）已是唯一状态表，2D 画布三视图已是派生投影（ADR-0002），但**没有投影一致性校验、没有生成后校验/修复管线、AI 技能提示词无"精确规格 vs 自由生成"双模式设计、几何/物理运算未做列式分解表达**。本文档针对这四个缺口给出提案；每条提案绑定可测量指标（基准任务预期得分），由 benchmark A/B 体系验证后再落地。

## 提案 a）状态与视图分离 + 投影一致性校验

- **论文依据**：结论 3——三视图不可唯一确定体素结构，自由生成时跨视图一致性不保证（0 vs 24 违规）。视图用于"看"，状态表用于"存"。
- **现状**：ADR-0002 已定 2D 画布 + 前/俯/侧投影，三维点集/items 是唯一状态；但投影一致性从未被校验（画布显示与数据可能漂移，历史上多次"画布所见非所得"事故）。
- **改动方案**：新增 `src/core/projection.ts`：给定 items（轴对齐盒/圆柱的 AABB 近似），确定性计算 TOP/FRONT/SIDE 三张投影图，并做三向存在性一致性检查（TOP 填充格 (x,z) 必须 ∃y 使 FRONT[x][y]∧SIDE[z][y]，对称三方向），输出 violation 清单。挂到校验/修复管线（提案 b）与 API（阶段 3 落地 `api/validate-model.ts`）。
- **影响面**：纯新增模块 + 新 endpoint；不改编码器、不改输入契约。零回归风险。
- **可测量指标**：基准任务不受影响（基准不直接评视图），指标 = 管线在 T4 自由生成输出上的"投影一致性违规数"下降（诊断指标，随修复管线一起观察）；产品侧：`validate-model` 在画布事故回归样例上的检出数。
- **风险与回滚**：无破坏性；若判违规过多误报（悬空合法场景），按论文教训（悬空块误报）设"仅告警不惩罚"模式。回滚 = 删除 endpoint。

## 提案 b）生成后确定性校验 + 自动修复管线

- **论文依据**：结论 4——"生成后跑不变量校验并自动修复（补内部地板、补门高、补支撑）"，自由生成失败模式可被确定性后校验捕获，无需重新生成。
- **现状**：生成器（src/draw/generate.ts）确定性产出元件，但无任何不变量校验；静默输出坏模型（如腿悬空、元件穿模、底不贴地）是当前行为。
- **改动方案**：新增 `src/benchmark/repair.ts`（基准版本组件，成熟后提升为 `src/core/invariants.ts` + `src/core/repair.ts`）：
  - 校验：贴地（底 y∈[−ε,ε]）、支撑（底面中心落在支撑体顶面或地面）、轴对齐（非轴对齐记违规）、正尺度、无穿模、比例约束；
  - 修复（保守，只修明确违规）：贴地吸附（|底|<0.05 → 底=0）、支撑修复（悬空且下方有支撑体 → 下降到支撑面）、近似重复元件去重、近轴对齐吸附；
  - 输出结构化诊断 `{violations, fixes, ok}`，修复不了的违规如实报告——不静默。
- **影响面**：基准侧新模块；产品侧新 endpoint（`api/validate-model.ts`）与 `/api/draw-model` 可选 `options.repair`（默认关闭，向后兼容）。
- **可测量指标**：基准任务 T4/T5 预期得分提升（T4 不变量违规数下降；T5 支撑/贴地违规下降），T1/T2/T3 预期不变（修复幂等性：合法结构修复后逐位不变，单测保证）。趋势表：round1（v0 vs v1=仅修复管线）即验证。
- **风险与回滚**：修复可能改坏精确规格输出 → 用幂等性单测 + 保守阈值（仅修复明确违规）；若 round1 数据表明修复净损失，回滚 = 版本配置切回 identity 管线。

## 提案 c）面向"自由生成"的输入协议（精确规格 vs 功能要求双模式）

- **论文依据**：结论 1/2/6——精确规格下怎么表示都满分；自由生成才是分水岭；提示词协议必须区分"逐条规格"与"仅功能要求"两种模式。
- **现状**：AI 技能/API 无协议层设计——任务描述混用精确与模糊表述，模型无"规格执行 vs 自主设计"的明确模式切换。
- **改动方案**：基准体系先行定义两种协议模式（协议文本 v0 直接生成 / v1 分层 2D 推理），由 A/B 数据选出候选，再落进产品：
  - 模式一（精确规格）：提示词逐条枚举规格，模型机械执行；
  - 模式二（自由生成）：只给功能要求 + 不变量自检清单（贴地/支撑/净空/对称/比例），模型自主布局；
  - 回退策略：输出不满足解析/不变量 → 进入修复管线（提案 b），修复无效则返回结构化诊断而非坏模型。
- **影响面**：基准协议文件（benchmark/protocols/*.txt）；产品侧 AI 技能提示词模板（后续落地）。
- **可测量指标**：基准 T4 得分（v1/v2 协议 vs v0 预期 +0.1~0.3）；T1 得分不因协议切换下降（精确模式守恒）。
- **风险与回滚**：协议文本影响全部任务 → 每次协议变更只作为候选版本进 B 会话，采纳规则（B 全部 ≥ A）兜底。

## 提案 d）可分解的几何/物理运算按轴/按视图列式分解

- **论文依据**：结论 5——列式物理（重力）是 2D 压缩的理想形态：按 (x,z) 列分解为独立 1D 问题，模型精确执行；"压缩成二维"的价值正在于此。
- **现状**：无分解表达。生成器一次处理整笔笔画；AI 建模一次描述整个三维结构。
- **改动方案**：
  - 基准侧：T5 重力求解器按列分解（确定性代码），提示词按"逐列/逐层"描述输入输出；
  - 产品侧（后续）：API/AI 技能的任务模板支持"分轴/分层"描述（如"先定 XZ 布局，再沿 Y 逐层堆叠"），生成器已具备的确定性几何运算（段拟合、旋转、堆叠）显式声明为"代数兜底"，模型提示词不再要求心算三维。
- **影响面**：基准协议 + 提示词模板；无数据契约变更。
- **可测量指标**：T5 得分（预期满分保持）、T4 分层协议得分（预期提升，同提案 c 的 v1/v2）。
- **风险与回滚**：无破坏性；协议层回退即删除对应协议版本。

## 实施顺序（与 benchmark 优化轮次对应）

1. 先校验器/诊断（提案 a/b 的校验部分：不改变输出语义）——round 1 候选版本 v1；
2. 再修复管线（提案 b 修复部分）——round 1~2；
3. 再协议调整（提案 c/d：分层 2D 推理协议）——round 2~3；
4. 落地产品接口（api/validate-model.ts 等）——数据支持后。

## 全局约束

- 不破坏 29 条 golden 测试与向后兼容；breaking 变更必须另行提案并先确认。
- 所有优化绑定基准任务可测量指标；采纳规则：候选版本全部任务得分 ≥ 基线才采纳，否则回滚并分析。
