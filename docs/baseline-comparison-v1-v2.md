# 基线 v1 → v2 对比：知识前置 + 工具改进的效果（2026-08-14）

> 对照实验：同任务（自由画风扇，8 条相同断言），v2 增加 drawing-rules.md 可读 + gms.list()/summary 归一化/perStroke 映射 + 强制先 clear。

## 结论

1. **知识前置假设验证成功**：两模型迭代轮数 3-4 → 2；探针轮归零（v1 的 50-60% 轮数）；ds 时长 -33%、成本 -45%。
2. **质量提升**：v1 两模型都不做的桨距角/同面/后罩（G13/G5），v2 都主动做；rotate 索引零错误（G7/G14 + gms.list）。
3. **gpt 时长持平的解释**：省下的探针时间被文档阅读与更深的验证习惯（每步 summary+截图+数据断言）吸收——产出更高质量（工具调用 -33%、错误归零、一次 API 核验直接抓出支架悬空）。ds 更"俭省"：读文档后直接按 §2 画，时间/成本双降。
4. **模型反哺文档**：ds v2 发现 3 个文档不一致（椭圆长宽比上限 4:1 拒收未注、半径/直径混用、bbox.m 与归一化坐标不一致）——已修入 drawing-rules v1.1。这是"模型层 → 文档层"的闭环第一次跑通。

## 下一步候选

- gpt 的 15 分钟仍是单次成本大头：可测"断言驱动最小验证"（模板给定核验代码，砍验证轮）
- 长宽比上限进服务端识别文档（generate.ts fitStroke 的椭圆判据），或加后端友好错误（"椭圆长宽比超 3:1"）
- 底座 4:1 椭圆被拒是 G12 的实证——G12 应补具体数值（≤2:1 安全）

## v3（组件化接口，2026-08-14）：gms.part + inspect --stroke + 组件文档

| 指标 | v1 | v2 | v3 | v1→v3 |
|---|---|---|---|---|
| 时长 | 750s | 504s | **196.5s** | **-74%** |
| 成本 | $0.055 | $0.030 | **$0.0127** | **-77%** |
| 工具调用 | 31 | 45 | 25 | -19% |
| 核心建模轮数 | ~14 探针 + 3 | 0 探针 + 2 | **1（7 行 gms.part 一次成型）** | — |
| 几何推导/抓包调试 | 大量（TURN 2 ~300 行思考） | 部分（底座 400 二分 9 轮） | **零**（part 自动 px/lift/闭合/颜色；inspect --stroke 单笔核验） | — |
| 结果 | 8/8 | 8/8 | 8/8 | = |
| 立体感（桨距/同面/后罩/配色） | 0 | 部分 | **全套（G13）** | + |

### v3 剩余摩擦（非能力缺口）

- rotate 索引：连续两次 rotate 未即时核对 → 错复制 → gms.list() 修复（G7 纪律问题）
- undo 批次粒度：连续 undo 按"每 gms 调用一批"回退，可能撤掉非目标笔画 → 撤销后必须 list() 核对
- 这两个点在 v4 可考虑：rotate 返回"新副本索引"提示，或 undo 支持指定数量

### 三代结论

1. 知识前置（v2）：探针归零，时长 -33%/成本 -45%
2. 组件化声明（v3）：几何推导归零，时长再 -61%（v2→v3），累计 -74%；成本累计 -77%
3. 模型反哺循环跑通两轮：v2 反哺文档 3 点（长宽比/半径/bbox.m）→ v1.1；v3 反哺 rotate/undo 操作纪律 → 已进 G7/G9 与本节
4. **"组件 = 一行声明"是模型层的正解**：用户洞察（每个组件只需位置/旋转/颜色/缩放）由 gms.part 落地；文档只讲"怎么声明组件"
